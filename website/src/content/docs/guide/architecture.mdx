The picture below is the intended layering in [SPEC §3](https://github.com/tomiok/persiaDB/blob/main/SPEC.md#3-architecture-overview).
`persia-format`, `persia-storage`, `persia-engine` (schema, documents, manifests, and a segment builder, writer, and reader), and `persia-analysis` contain library code.
`persia` exports no `Db`. `persia-server` is an empty `main`. `persia-blob` and `persia-proto` are module docs only.
[`docs/architecture.md`](https://github.com/tomiok/persiaDB/blob/main/docs/architecture.md) is the contributor map (crate graph, write path, query
path) and stays the place for that detail.

Three rules shape the rest of the design:

1. **Immutable segments and append-only metadata.** Crash recovery, caching, and replication all
   read a snapshot instead of locking a mutable index.
2. **The same logical objects everywhere.** A segment, manifest, WAL chunk, or blob is a named
   object. Locally they are frames in one file; remotely they are one object each. The segment
   bytes do not change between the two.
3. **The engine is synchronous.** It talks to I/O only through the `Storage` trait. Async belongs
   in the cloud backends and in the server.

| Crate | Role | Status |
|---|---|---|
| `persia-format` | Encodings, checksums, frames, block codecs. No I/O policy. | Implemented (M1) |
| `persia-storage` | `Storage` trait, memory, local file, later S3 / GCS / Azure. | Memory, local file, and the container are implemented (M2). Cloud is M12. |
| `persia-analysis` | Tokenizers, normalizers, stemmers, analyzers. | Done (M4). It does not search. |
| `persia-engine` | Schema, segments, WAL, commit, merge, query, BM25F, relaxation. | Schema, documents, and manifests exist (M3). A segment builder, writer, and reader exist (M5). Query, the WAL, and relaxation do not (M6–M8). |
| `persia-blob` | Content-addressed chunks, dedup, garbage collection. | No API yet (M9) |
| `persia` | The embedded API: `Db` and `Collection`. | Not implemented (M10). The crate exports no types. |
| `persia-proto` | `persia.proto` and committed generated code. | Module docs only (M11) |
| `persia-server` | gRPC and HTTP. Roles: writer, reader, router. | Empty `main` (M11, M13) |
| `persia-cli` | Sweep temporary and quarantine files. `inspect segment` and `dump segment` read one segment (`--verify` checks it). `compact`, `bench`, import, and search are later. | Sweep, inspect, and dump exist. The rest is M10. |

Dependencies point downward only (`persia-format` at the bottom). `cargo xtask check-deps` enforces
the graph. The public facade orders blob writes before the document commit so the engine never has
to know about blob bytes (SPEC §9.5).

On a query, once the engine exists: analyze the text, search each segment and the memtable, merge
the per-segment top-k, and if there are too few hits run the relaxation cascade. The response
includes which level matched.
